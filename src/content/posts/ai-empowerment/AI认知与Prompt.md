# AI认知与Prompt

这份课程笔记虽然原始内容几乎全是截图，但主线非常清楚：先建立对大语言模型的基本认知，再理解传统 NLP 为什么会被改写，最后落到 Prompt 为什么会成为今天使用大模型的核心接口。  
如果按学习逻辑重组，它更适合作为一篇“刚接触 AI 应用时，应该先建立哪些基础判断”的入门文章。

## 一、先别急着写 Prompt，先知道大模型到底在擅长什么

课程里先总结了大语言模型的四种基本能力：

- `总结能力`：从文本中提取关键信息，概括核心内容
- `推断能力`：基于上下文进行逻辑推理或分类判断
- `转化能力`：实现改写、翻译、风格转换等任务
- `扩展能力`：根据提示补全或生成更丰富的文本内容

这四项能力几乎覆盖了大多数日常 AI 使用场景。  
换句话说，Prompt 之所以重要，不是因为模型什么都不会，而是因为模型本来就有这些潜力，Prompt 负责把潜力引导到正确方向。

## 二、大模型为什么改写了传统 NLP 的工作方式

课程里把传统 NLP 和大模型新范式做了对比，这一点非常值得保留。

### 1. 传统 NLP 的特点

传统做法通常是：

- 一个任务训练一个模型
- 每个任务都要单独准备数据、训练、调优
- 开发链路长，成本高

### 2. 大模型带来的变化

今天的大模型更像“一个通用能力底座”：

- 一个模型可以覆盖多类任务
- Prompt 工程成为关键驱动手段
- 开发重心从“为每个任务重新造模型”，转向“如何更好地组织任务描述和上下文”

课程里对这种变化的总结很精炼：

- 模型定位从“专用”走向“通用 + 提示引导”
- 开发流程从“数据标注、训练、调优”，转向“模型选择与 Prompt 设计”
- 大幅缩短算法开发周期

这也是为什么今天很多应用团队并不自己训练模型，但依然可以快速做出 AI 功能。

## 三、把大模型用起来，最关键的不是模型名，而是这三步

课程里把“大模型使用三要素流程”总结成三步：

1. 明确业务问题
2. 选择基础模型
3. 设计有效 Prompt

这三步其实非常像一个决策链。

### 1. 先把问题讲清楚

不要直接问“模型能不能帮我做这个”，而是先把业务问题翻译成明确任务：

- 是总结、分类、抽取，还是生成
- 目标是什么
- 输出要服务哪个环节

### 2. 再选择合适模型

课程里提到：

- 可以根据任务特性匹配模型能力
- 选择合适的预训练大模型

这说明模型选择不是“越大越好”，而是“是否适配当前任务”。

### 3. 最后用 Prompt 做认知对齐

Prompt 的作用，本质上是：

- 把人的目标翻译给模型
- 把输出边界约束清楚

也就是说，Prompt 不是附属技巧，而是人和模型之间的工作接口。

## 四、为什么 Transformer 是理解大模型绕不过去的一层

课程里专门提到 Transformer 的核心地位，这部分很值得保留成基础认知。

### 1. Transformer 为什么重要

它在 2017 年由论文《Attention Is All You Need》提出，之后成为现代大语言模型的底层核心架构。

### 2. 它的关键优势

课程里提到几个点：

- 完全基于自注意力机制
- 摆脱了 RNN / LSTM 的序列依赖限制
- 能更灵活地获取上下文
- 支持并行训练

### 3. 为什么这会带来行业级影响

因为它既提升了训练效率，也突破了传统序列模型在长上下文建模上的限制。  
没有 Transformer，就很难有今天这个规模和能力层级的大模型。

## 五、大模型为什么能在文本分类等任务上超过传统方案

课程里举了“文本分类任务”的例子，重点不是分类本身，而是说明大模型应用方式的变化。

### 1. 传统方案的问题

过去要做文本分类，常常需要：

- 准备专门数据集
- 训练分类模型
- 重复维护模型和标注流程

### 2. 大模型方案的特点

借助 `Prompt + 示例`，大模型可以直接做分类判断，并展现出几个优势：

- 准确率提升
- 输入适配性更强
- 流程更高效，维护成本更低

课程里还给出一个很现实的启发：  
大模型不只是“能生成文字”，还在很多理解类任务上改写了原有的工程流程。

## 六、开源还是闭源，不是信仰问题，而是四个维度的权衡

课程里对闭源与开源模型做了对比，这部分对做应用选型的人尤其重要。

### 1. 闭源模型

以 ChatGPT、GPT-4 这类为例，优势通常是：

- 参数规模大
- 效果强

代价通常是：

- 成本更高
- 数据安全与控制边界要额外评估

### 2. 开源模型

以 Llama、千问、ChatGLM 等为例，优势通常是：

- 灵活可控
- 支持微调和本地部署

代价通常是：

- 效果上限可能略低
- 需要更多 GPU 与工程资源

### 3. 选型时至少看四个维度

课程里列出的评估维度很实用：

- 效果
- 安全性
- 成本
- 部署方式

所以真正成熟的模型选型，不是“哪个最火”，而是“哪个更适合你的业务边界”。

## 七、Prompt 不是“会不会提问”，而是“会不会约束输入输出边界”

课程后半段开始从 Prompt 基础认知转向实践，里面最有价值的不是花哨技巧，而是几个工程上很稳的原则。

### 1. 用分隔符防止 Prompt 注入

课程里强调：

- 要明确分隔“指令”和“数据内容”
- 使用清晰分隔符，比如 `"""`、`<<< >>>`、`<tag>`

它的作用在于：

- 划清语义边界
- 降低外部输入“劫持指令”的风险
- 提升模型解析稳定性

这已经不是“写提示词更优雅”，而是基础安全约束。

### 2. 要求结构化输出，才能让结果可处理

课程里对结构化输出讲得很实用：

- 可以要求 JSON、HTML、XML 等格式
- 提前定义字段名和字段类型
- 让程序可以直接解析

这样做的价值包括：

- 减少人工二次整理
- 支持自动化流程和系统集成
- 提高结果的稳定性和可用性

如果 Prompt 最终要接系统，而不仅仅是给人看，结构化输出几乎是必须能力。

## 八、Prompt 的作用，本质上是在做人和模型之间的认知对齐

把这门课压缩一下，Prompt 的真正价值其实只有一句话：

**Prompt 决定模型是在“猜你的意思”，还是在“按你的边界工作”。**

大模型本身有能力，但如果没有：

- 清晰的问题定义
- 合适的上下文
- 明确的输出约束

它就很容易给出“看起来有道理，但不够稳定”的结果。

## 九、把这份笔记压缩成一条适合入门复习的主线

如果只保留最核心的学习顺序，这篇笔记可以压缩成下面这条链：

1. 先理解大模型的四种基础能力
2. 再理解传统 NLP 为什么会被“通用模型 + Prompt”改写
3. 建立三步使用流程：明确问题、选择模型、设计 Prompt
4. 补上 Transformer 这层基础认知，理解大模型为什么可行
5. 理解大模型在分类、理解、生成任务上的工程价值
6. 学会在闭源与开源模型之间做现实权衡
7. 最后把 Prompt 当成输入边界、输出格式和安全约束的控制器

## 十、这份课最重要的心法

课程真正想传达的不是“AI 很强”，而是：

**大模型提供能力上限，Prompt 决定落地质量。**

当你理解了：

- 模型擅长什么
- 模型不擅长什么
- 该怎样选模型
- 怎样约束输入和输出

你就不再是在“试试看 AI 会不会”，而是在有方法地把 AI 变成一个可控工具。
