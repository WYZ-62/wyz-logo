# React

这份课程笔记基本全由截图组成，但知识线很完整：先讲 React 是什么，再从 JSX 入门，接着进入 props、state、条件渲染、列表渲染、ref，最后对比类组件和函数组件，并落到 `useState`、`useEffect` 这些最常见的 Hooks。  
如果按学习逻辑重组，它更适合作为一篇“React 从基本认知到函数组件核心用法”的入门与复习文章。

## 一、先理解 React 在前端里到底扮演什么角色

课程开头先定义了 React：

- 它本质上是一个用于构建用户界面（UI）的 JavaScript 库
- 核心思想是组件化开发
- 在 MVC 里更接近 View 层

这三点里最关键的是“组件化”。

因为 React 的真正价值，不只是“能写页面”，而是把页面拆成：

- 独立的小单元
- 可复用的模块
- 可组合的结构

这也解释了为什么它特别适合：

- 中大型前端项目
- 需要多人协作的页面开发
- 需要维护和迭代的交互系统

## 二、最简单的上手方式：先用 CDN 跑起来

课程没有一开始就进入脚手架，而是先给出了通过 CDN 引入 React 的方式，这很适合入门。

典型的最小环境包括：

- `react.development.js`
- `react-dom.development.js`
- `babel.js`

它们分别承担：

- React 核心能力
- DOM 渲染能力
- JSX 转译支持

这种方式的意义不在于适合生产环境，而在于：

- 零门槛起步
- 快速验证概念
- 先理解 React 的运行方式，再进入工程化工具链

## 三、JSX 是 React 的第一道门槛，也是最基础的表达方式

课程对 JSX 的解释很清楚：

- JSX 是 JavaScript 的语法扩展
- 允许在 JS 中直接编写类似 HTML 的结构
- 最终会被 Babel 转译为普通 JavaScript

### 1. JSX 不是 HTML

这是最容易误解的一点。  
课程里明确说了：

- JSX 本质上不是 HTML
- 它是 `React.createElement()` 的语法糖

也就是说：

```jsx
<h1>Hello</h1>
```

最终会变成类似：

```js
React.createElement("h1", null, "Hello")
```

### 2. JSX 的意义

它的价值主要体现在：

- 更接近 UI 的声明式写法
- 让结构和逻辑能更自然地写在一起
- 成为后续组件化表达的基础

## 四、JSX 不是自由文本，它有自己的一套语法规则

课程里总结了几个最常见、也最容易出错的地方。

### 1. `className` 和 `style`

在 JSX 中：

- 用 `className` 替代 `class`
- `style` 使用对象形式

例如：

```jsx
<div className="card" style={{ backgroundColor: "red" }} />
```

原因并不复杂：

- `class` 是 JavaScript 保留字
- `style` 要通过对象形式才能被 JS 正常处理

### 2. JSX 表达式必须返回有效 React 元素

课程里还强调了：

- JSX 大括号里必须是可返回值的表达式
- 不能把 `for`、`let` 这种语句直接塞进去

允许的通常是：

- 三元表达式
- 函数调用
- 数组 `map`

这些规则看起来细碎，但本质上都在服务一件事：  
让 UI 结构能稳定转成 React 元素树。

## 五、props 解决的是“组件之间怎么传数据”

课程对 `props` 的定位很准确：

- 它是组件对外的参数对象
- 用来实现父组件到子组件的数据传递

### 1. props 的设计目的

主要包括：

- 让组件支持动态配置
- 支持复用
- 建立组件组合关系

### 2. props 的基本规则

课程里特别强调了两点：

- 任何类型的参数都可以通过 props 传递
- props 是只读的，不能在子组件中直接修改

### 3. `children` 是一个特别重要的 props

`children` 用来表示组件包裹的内容，它让 React 更容易实现：

- 插槽式复用
- 通用布局组件
- 更灵活的组合结构

所以 props 的意义不只是“传值”，它本质上定义了组件的输入边界。

## 六、state 解决的是“组件自己怎么管理变化”

课程里把 state 定义成：

- 组件内部可管理、可变化的数据容器
- 驱动界面更新的核心机制

### 1. state 的核心作用

它的重要性主要有三点：

- 数据变化后自动触发组件重渲染
- 让组件拥有内部状态
- 为副作用和复杂状态管理打基础

### 2. `useState` 的基本用法

课程给出的重点很实用：

- 返回 `[stateValue, setState]`
- `setState` 用于更新状态
- 更新是异步批处理的，不是立刻同步改值

### 3. 不可变更新原则

课程里专门强调了：

- 不能直接修改对象或数组
- 要返回新的引用

例如不要这样：

```js
arr.push(x)
obj.key = value
```

而应该用：

```js
setArr([...arr, x])
setObj({ ...obj, key: value })
```

这一点其实是 React 状态更新稳定性的基础。

## 七、条件渲染和列表渲染，是 React 中最常见的 UI 分支控制

### 1. 条件渲染

课程里给出的常见方式包括：

- `if / else`
- 三元表达式
- 逻辑与 `&&`

它们分别适用于：

- 完整分支判断
- 行内切换
- “有就显示，没有就不显示”的场景

### 2. 列表渲染

React 里通常使用数组的 `map()` 来渲染列表。

而这时最关键的不是 `map` 本身，而是 `key`：

- key 用来帮助 React 识别节点身份
- 应优先使用稳定的业务 ID
- 不推荐随意用 `index`

课程明确提到：

- key 不稳定会带来状态错乱和性能问题

这说明渲染列表时，数据结构和渲染策略是绑定在一起的。

## 八、React 组件的真正意义，是把 UI 组织成可组合的函数单元

课程后面专门定义了 React 组件：

- 组件是独立、可复用、可组合的 UI 单元
- 本质上是接收 `props` 并返回 JSX 的函数或类

它的核心特征包括：

- 封装性
- 可组合性
- 声明式渲染

这也是为什么后续所有 React 开发，最终都建立在“组件树”的组织方式上。

## 九、ref 是 React 留给你操作真实节点和实例的“逃生门”

课程里对 `ref` 的定义和应用场景讲得很实用。

### 1. ref 是什么

- 用于获取 DOM 元素或组件实例的直接引用
- 是 React 提供的特殊能力

### 2. 常见用法

- 用 `useRef()` 创建 ref
- 在 JSX 中通过 `ref={myRef}` 绑定元素
- 再通过 `myRef.current` 调用 DOM 方法

例如：

- `focus()`
- `scrollIntoView()`

### 3. 典型场景

课程中提到：

- 焦点控制
- 动画实现
- 第三方库集成

这说明 ref 不是替代 React 状态管理，而是专门用于处理那些“必须碰真实节点”的场景。

## 十、从类组件到函数组件，React 的主线已经很明确

课程后面做了类组件与函数组件的对比，这是 React 学习中非常关键的一步。

### 1. 二者的共性

- 都通过 `props` 接收输入
- 都返回 UI

### 2. 核心差异

#### 状态管理

- 类组件：`this.state + this.setState()`
- 函数组件：`useState`

#### 生命周期

- 类组件：`componentDidMount` 等钩子
- 函数组件：`useEffect`

#### 性能优化

- 类组件：`shouldComponentUpdate`
- 函数组件：`useMemo / useCallback`

### 3. 迁移趋势

课程里给出的结论非常清楚：

- 主流趋势是函数组件 + Hooks
- 状态逻辑更适合通过 Hooks 抽象
- 类组件更多是理解历史和兼容旧代码

## 十一、`useEffect` 本质上是在函数组件里模拟生命周期

课程里专门讲了 `useEffect` 与类组件生命周期的等价关系。

### 1. 挂载时执行

```js
useEffect(() => {
  // 组件挂载
}, [])
```

### 2. 依赖变化时执行

```js
useEffect(() => {
  // 依赖更新
}, [deps])
```

### 3. 卸载前清理

```js
useEffect(() => {
  return () => {
    // 清理逻辑
  }
}, [])
```

课程里最值得保留的提醒是：

- 空依赖数组意味着只执行一次
- 依赖变化会重新触发 effect
- 清理函数用于销毁前的善后

这说明 `useEffect` 不只是“写副作用的地方”，它实际上承担了函数组件里的生命周期管理责任。

## 十二、把这份笔记压缩成一条适合复习的学习主线

如果只保留最核心的学习顺序，这篇 React 笔记可以压缩成下面这条链：

1. 先理解 React 是 UI 组件库，核心思想是组件化
2. 再用 CDN 方式快速搭建最小运行环境
3. 学会 JSX 是 `React.createElement()` 的语法糖
4. 理解 props 负责组件输入，state 负责内部变化
5. 掌握条件渲染、列表渲染和 key 的基本规则
6. 认识 ref 处理真实 DOM 和第三方交互的作用
7. 从类组件对比中理解函数组件与 Hooks 的主流地位
8. 最后掌握 `useState` 和 `useEffect` 这两个最核心的 Hooks

## 十三、这份课最重要的心法

课程真正想说明的，并不是“记住几个 Hook 名字”，而是：

**React 的核心不是 API 数量，而是组件、数据和渲染之间的关系。**

一旦你理解了：

- JSX 只是 UI 的声明方式
- props 是外部输入
- state 是内部变化源
- 渲染是数据变化后的自然结果

你后续再学：

- 路由
- 状态管理
- 表单
- 性能优化

都会更容易，因为这些能力本质上都建立在这条最基础的 React 心智模型之上。
